# Evaluation metrics commitment (Workbook 2, section 4.4)

This file records Table 4.4.1 of Workbook 2 section 4.4 in the repository, so that the metrics have a dated, reviewable record
in Git. The metrics are committed before any Model 1 result exists and are not revised after results are seen; any later change is
listed in the amendment log at the end.

How to read the dates: **Committed on** is the date given in Workbook 1 or Workbook 2 for that row. **Evidence in Git** is what the
repository can show: rows marked `eval_protocol.json` are defined in `docs/data_run/records/eval_protocol.json` (frozen with the
dataset, manifest created 2026-10-18 UTC, in the repository since commit `ddc1662`, 2026-11-06; the Model 0 full grid ran on 2026-11-07).
Every row is also recorded by the commit that adds this file.

| Paired significance test on per-user NDCG@10, with a 95% confidence interval for the difference | A difference in mean NDCG@10 can come from a few users. A paired test on the same users shows whether it is larger than chance. Most users score 0 under both models, so a two-sided paired randomization (sign-flip) test on the mean per-user difference is used instead of the Wilcoxon signed-rank test, which drops tied pairs. 10,000 permutations, plus a paired bootstrap 95% interval (10,000 resamples of users), random seed 2026. Holm correction across the comparisons in one results table, significance level 0.05. Recall@10 and MRR differences are reported with the same interval but are not used for decisions. | Full-catalog test split, all 56,017 users. For a model trained with seeds 42, 43 and 44, each user's NDCG@10 is the mean over the three seeds. Comparisons: Model 1 against Model 0, and Model 0 and Model 1 each against popularity, Markov and item-kNN. Cold-start: Model 1 against Model 0 on the 1,142 cold test cases, using each case's relative rank. | November 22, 2026 | This file (amendment of 2026-11-22) |
| Retrieval Recall@10 and Recall@50 (RAG step of the multi-agent prototype) | Requested by the professor at Checkpoint 3. Measures whether the retrieval step finds the true next item before any LLM step runs, so retrieval errors are separated from generation errors. | Item-text index built from training data only. Retrieval settings chosen on the validation split, test split reported once. Prototype checks (valid product IDs, no already-seen items, rate of "no suitable match" answers, manual grounding check) on a fixed set of 50 test requests drawn with seed 2026. | November 22, 2026 | This file (amendment of 2026-11-22) |
| G-Eval scores (1 to 5) for faithfulness, relevance, coherence and fluency | Requested by the professor at Checkpoint 3. Ranking metrics cannot judge generated text. G-Eval (Liu et al., EMNLP 2023) uses a judge LLM with fixed evaluation steps and takes the probability-weighted mean of the score tokens, or the mean of 20 samples if token probabilities are unavailable. The judge is from a different model family than the generator, and the judge model, its revision and the prompts are committed to the repository before the first output is scored. Used for language quality only, never to choose a ranking model. | Explanations from the 50 fixed prototype requests, and the LLM profiles of 50 users drawn with seed 2026. Two team members score the same outputs independently. The Spearman correlation between G-Eval and the mean human score, and the agreement between the two people, are reported for each criterion. A criterion whose G-Eval scores do not correlate positively with the human scores (Spearman rho at most 0 or p at least 0.05) is reported as unreliable. | November 22, 2026 | This file (amendment of 2026-11-22) |

Optional additional metric for 298B, only if the team decides to include it: attribute-inference accuracy of the LLM attacker against chance,
with attributes defined from data that exists (categories, brands, price tier, held-out purchases). It does not replace the membership-inference AUC.
